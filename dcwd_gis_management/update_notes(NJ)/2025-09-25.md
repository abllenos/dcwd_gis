## Enhancements
### 1. Table Column Sorting Added
| Page | Columns Now Sortable | Sorter Type |
|------|----------------------|-------------|
| Classification | ID, Layer Name, Class Name | Numeric ID; string localeCompare |
| Class | ID, Date Inserted | Numeric ID; timestamp compare |
| Layer | ID, Date Inserted | Numeric ID; timestamp compare |

Implementation notes:
- Numeric IDs: `(a, b) => a.id - b.id` (IDs coerced to number during normalization)
- Strings: `a.layerName.localeCompare(b.layerName)` / `a.className.localeCompare(b.className)` (base locale, stable)
- Dates: `new Date(a.dateInserted).getTime() - new Date(b.dateInserted).getTime()` safeguarded by simple existence checks
- All sorter functions are pure and side‑effect free to avoid unnecessary MobX reactions.

## Additional changes (2025-09-25 continued)

During follow-up work today the following practical fixes and improvements were applied to make the Logs UI and geometry rendering reliable in local development (DEV) while retaining the long‑term plan to remove dev proxies once server CORS is fixed:

- Fixed a syntax/logic bug in `vite.config.ts` where a duplicate `rewrite` entry for the `/api/layers` proxy caused an invalid config. The proxy was corrected.
- Added TEMPORARY dev proxies for the geometry endpoint paths:
	- `/helpers/gis/api/UserLogs/getLogsGeometry.php`
	- `/helpers/gis/api/userlogs/getlogsgeometry.php` (defensive lowercase)
	These map to `https://api-gis.davao-water.gov.ph` and allow the frontend to fetch log geometry during local development.
- Updated `logUiStore.ts` geometry fetch to explicitly request the geometry via the local proxy (`useLocalProxy: true`) and mark the request as public (`skipAuth: true`) so no Authorization header is sent for this public endpoint.
- Replaced the Google Maps-based `MapView` with a Leaflet implementation (`MapView.tsx`) so the map no longer requires a Google API key (eliminates ApiProjectMapError / NoApiKeys failures). The Leaflet map renders markers, polylines, and polygons from the geometry coordinates returned by the geometry endpoint.
- Implemented server-side paging for the Logs list:
	- `logStore.fetchLogs()` now sends `PageIndex` and `PageSize` to `admin/logtrails/get` and constructs the request URL accordingly.
	- `logStore` now parses server paging metadata (`data.count` / `data.totalCount`) and exposes `totalCount` for the UI.
	- `LogPage.tsx` pagination now uses `totalCount` and calls `logStore.updatePagination(page,size)` to drive server paging.

These follow the repo constraints: no new axios instances were introduced; dev proxies are marked TEMPORARY and documented; no `useState` was added; changes kept small and focused.
