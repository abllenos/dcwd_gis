# Update Notes — 2025-09-24

- Hardened geometry (Log details map) request: removed Authorization header for a public endpoint to satisfy CORS.

- Added in-modal diagnostics for geometry fetch (URL + HTTP status) to speed up troubleshooting.
- Wrapped all `logUiStore` state mutations inside MobX actions (`runInAction`) to satisfy strict mode.

- Retains existing token injection & refresh flow for all other endpoints.
- Still removes `Content-Type` on GET to reduce unnecessary preflights.

### Supplemental: Maintenance Pages Integration (Classification, Class, Layer)
Date context: Work initiated 2025-09-24 (carried into 2025-09-25) but foundational proxy + normalization approach established today, so documenting here for continuity.

#### Overview
Replaced temporary seed/fake data for three maintenance pages with live legacy PHP endpoints that currently lack permissive CORS headers. Implemented a DEV‑only proxy strategy plus defensive tuple/object normalization and diagnostics.

#### Endpoints (Legacy PHP)
- Classification: `.../getAllClassification.php`
- Class: `.../getAllClass.php`
- Layer: `.../getAllLayer.php`

#### DEV Proxy Approach
- Added Vite dev server proxies mapping `/api/classifications`, `/api/classes`, `/api/layers` to the above legacy scripts.
- Each proxy rule is annotated with `TEMPORARY CORS WORKAROUND – REMOVE AFTER SERVER HEADERS FIXED`.
- Production (non-DEV) code paths bypass the proxy and call remote host directly (will still CORS-fail until server fixed; acceptable interim risk noted).

#### Normalization Pattern
- Legacy payload shape: `{ data: [ tuple | object, ... ] }` with tuples as ordered arrays (id, description, statusFlag, layerName, className) or objects with inconsistent key casing.
- Per-store normalization block (`// Normalization BEGIN/END`) converts each entry to a unified record: `{ id, description, className?, layerName?, dateInserted? }`.
- Guard clauses ensure only numeric `id` entries retained; malformed entries skipped.

#### Diagnostics
- Introduced standard fields per store: `lastUrl`, `lastStatus`, `lastFetchedAt`, `lastError`, plus optional `lastParseNote` for edge parsing notes (currently used in Classification store).
- Rendered inline under tables; earmarked for DEV-only gating in a future cleanup pass.

#### Error vs Empty Handling
- Network / thrown error: sets `lastError` and shows AntD `Alert`.
- Successful fetch but zero normalized records: shows AntD `Empty` component (no error banner) to differentiate connectivity vs absence of data.

#### Sorting (Planned for 2025-09-25 note)
- Sorting added subsequently (ID + selected descriptive/date columns). Details captured in the 2025-09-25 update file.

#### Technical Debt / Removal Tasks
- Track removal of each proxy once backend emits proper `Access-Control-Allow-Origin` and (if needed) `Vary: Origin` headers.
- Consolidate normalization into a shared utility (`normalizeMaintenanceRecord`) to reduce duplication and enforce consistent defensive checks.
- Gate diagnostics + console logs behind `import.meta.env.DEV`.

#### Risk / Mitigation
- Risk: Forgetting to remove proxies → production divergence. Mitigation: explicit tasks in daily update notes + acceptance checklist item.
- Risk: Inconsistent normalization leading to subtle UI mismatches. Mitigation: upcoming shared util with typed return.

#### Acceptance Checklist Additions (recap)

- DEV proxy clearly marked temporary.
- Normalization block present & isolated.
- Diagnostics fields set & minimal.
- No `any`; only narrowed `unknown`.
